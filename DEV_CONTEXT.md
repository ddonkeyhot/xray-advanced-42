## 2. Архитектурные требования и целевой стек

### 2.1. Протокол и транспорт (Inbound)
- **Протокол**: `VLESS` + `Reality`
- **Транспорт**: `xHTTP` (SplitHTTP / HTTP/2-HTTP/3 chunking)
- **Режим транспорта**: `packet-up` (дробление трафика на мелкие псевдо-REST запросы для преодоления DPI/ТСПУ поведенческого анализа).
- **План по портам**:
  - Выбор пользователем: ручной порт (по умолчанию 443) или случайный/кастомный порт.
- **План по маскировке (SNI / Reality)**:
  - Интерактивный диалог: пользователь может ввести свой домен либо выбрать опцию `random`.
  - При `random` — автоматический выбор из пула проверенных зарубежных CDN с поддержкой TLS 1.3 + HTTP/2 (ALPN `h2,http/1.1`), не входящих в черные списки РКН и не перенаправляющих на РФ-IP.

### 2.2. Маршрутизация и выходной узел (Outbound)
- **IPv4 Only**: `domainStrategy: "UseIPv4"` в outbound `freedom` для исключения кривой гео-локации и блокировок/капч Google/Cloudflare на подсетях IPv6 дата-центров.
- **Резервное определение IP**: Цепочка `icanhazip.com` -> `api.ipify.org` -> `ifconfig.me` -> `ip.sb` с коротким таймаутом.
- **WARP-интеграция (опционально)**: Возможность при установке включить Cloudflare WARP (через встроенный outbound wireguard Xray) только для специфических ресурсов (ChatGPT, стриминги), не затрагивая общий трафик и избегая проблем с банками/госресурсами.

### 2.3. Вспомогательные утилиты управления (CLI)
- `/usr/local/bin/xray-link` — единый генератор VLESS-ссылок и терминальных QR-кодов.
- `/usr/local/bin/userlist` — список активных клиентов.
- `/usr/local/bin/newuser` — создание клиента с валидацией имени, генерацией UUID и обновлением конфигурации.
- `/usr/local/bin/rmuser` — интерактивное удаление с защитой от удаления `main`.
- `/usr/local/bin/mainuser` — быстрый вызов параметров основного профиля.
- `/usr/local/bin/sharelink` — вывод ссылки/QR любого пользователя.
