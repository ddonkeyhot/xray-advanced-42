# 📜 Журнал изменений и архитектурных решений (CHANGELOG)

Все ключевые изменения, решения по архитектуре, безопасности и пользовательскому интерфейсу проекта **Xray Advanced 42** фиксируются в этом файле.

---

## 📌 [11 сентября 2026 г.] — Комплексная спецификация CLI, UX, жизненного цикла и отказоустойчивости

### 1. Архитектура обновления (`--upgrade` / `xray_upgrade`):
- **Интеллектуальный аудит версий**:
  - Перед обновлением скрипт опрашивает GitHub API и выводит сравнительную таблицу: Текущая версия ➔ Доступная версия (для ядра Xray-core, CLI-утилит и баз GeoIP).
  - Интерактивное меню выбора:
    1. Обновить всё разом (рекомендуется при наличии апдейтов).
    2. Обновить только бинарник ядра Xray-core.
    3. Обновить только скрипты управления и CLI-утилиты из репозитория.
    4. Обновить только базы GeoIP/GeoSite.
    0. Отмена.
  - Оповещение: если установлена актуальная версия, скрипт сообщает: `У вас уже установлена актуальная версия, обновление не требуется`.
- **Гарантия сохранности данных**:
  - Никаких затираний существующих клиентов или ключей Reality. Перед любым обновлением создается мгновенный снапшот конфига в `/var/lib/xray-advanced-42/backup/`.
  - Валидация перед перезапуском: `xray -test`. Если тест провален — мгновенный автоматический откат.

### 2. Чистый откат системы (`--restore`):
- **Для Xray (`install.sh --restore`)**:
  - Полная деинсталляция: остановка службы, удаление бинарников, конфигов `/usr/local/etc/xray/`, баз, cron-задач и всех CLI-команд из `/usr/local/bin/`.
- **Для безопасности (`secure.sh --restore`)**:
  - Возврат порта SSH на 22, включение парольной аутентификации, отключение и сброс UFW, остановка Fail2ban, удаление твиков `sysctl`.
  - **Защита от случайного запуска**: требование явного подтверждения вводом слова `RESTORE` заглавными буквами и предупреждение о необходимости знать пароль.

### 3. Серверный Blackhole для РФ (Защита от утечки IP):
- Добавлен серверный Outbound `block` (протокол `blackhole`).
- Первое правило в `routing.rules` проверяет:
  - `domain`: `["geosite:category-ru", "geosite:ru"]`
  - `ip`: `["geoip:ru", "geoip:private"]`
- Любые попытки обращения к ресурсам зоны `.ru` и российским IP сбрасываются прямо на сервере. Реальный IP VPS никогда не светится в системах мониторинга РФ.

### 4. Отказоустойчивый Cloudflare WARP:
- Регистрация учетной записи происходит без ручных действий через официальный REST API Cloudflare прямо из bash (`wg genkey` + `curl`).
- Настройки зашиваются в чистый Wireguard outbound Xray без сторонних демонов.
- **Отказоустойчивость**: если Cloudflare API недоступен, скрипт не прерывает установку, а мягко переключает сервер на прямой режим (`Direct`) и сообщает, что WARP можно подключить позже.

### 5. Автоматизация баз GeoIP и Health Log:
- Базы загружаются из доверенного репозитория `Loyalsoldier/v2ray-rules-dat`.
- Еженедельный крон: `/etc/cron.d/xray-geoip-update`.
- **Контроль целостности**: скачивание в `/tmp/` ➔ проверка размера (>1 МБ) ➔ валидация синтаксиса Xray ➔ атомарная подмена через `mv`. При ошибке сохраняется текущая рабочая база (fallback).
- **Человекочитаемый лог**: `/var/log/xray-advanced-42/health.log` формата:
  `[YYYY-MM-DD HH:MM:SS] [СТАТУС] [КОМПОНЕНТ] Человекочитаемое описание`.

### 6. Спецификация CLI-команд и UX-навигации:
- Все утилиты размещаются в `/usr/local/bin/` и доступны глобально.
- **Единый принцип возврата**: клавиша `[0]` всегда означает `[← Назад / На уровень выше]` (в главном меню `[0]` — выход в терминал).
- После выполнения действия (показ QR-кода, переключение WARP) экран очищается и возвращает пользователя в список клиентов с аккуратными отступами и рамками.
- **Состав команд**:
  - `xray_menu` (или `xray`) — главный TUI-пульт.
  - `userlist` — интерактивный список клиентов и карточки управления (показ кредов/QR, переключение WARP, смена SNI, удаление).
  - `newuser` — мастер создания клиентов с циклом `Создать еще? [y/N]`.
  - `show_problems` — дашборд здоровья сервера и просмотр лога инцидентов.
  - `xray_update_geoip` — принудительное обновление баз.
  - `xray_help` — справочник.
- **Отказ от отдельного бинарника `rmuser`**: удаление пользователей инкапсулировано исключительно внутри подменю карточки пользователя в `userlist` с запросом подтверждения `[y/N]`.

## 📌 [10 сентября 2026 г.] — Формирование базовой архитектуры и безопасности

### Что было реализовано:
1. **Скрипт защиты сервера (`secure.sh`)**:
   - Anti-lockout защита: проверка наличия публичного ключа в `~/.ssh/authorized_keys` перед отключением паролей.
   - Смена порта SSH на случайный или заданный.
   - Конфигурация OpenSSH: отключение паролей (`PasswordAuthentication no`), поддержка сокетов systemd.
   - Настройка UFW: закрыты все входящие порты, кроме SSH и Xray.
   - Настройка Fail2ban с баном на 1 час после 3 попыток.
   - Включение `unattended-upgrades` и твиков безопасности ядра `sysctl`.
2. **Базовый антиблокировочный стек Xray**:
   - VLESS-Reality с транспортом `xHTTP` в режиме `packet-up`.
   - Пул совместимых SNI маскировки (Apple CDN).
   - Индивидуальная маршрутизация WARP на основе поля `user: ["email"]`.
   - Отказ от жесткого автосоздания `mainuser` в пользу интерактивного предложения создания первого пользователя в конце установки.
